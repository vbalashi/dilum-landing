# Website languages and learning collections

## URL and ownership policy

English remains the default at existing unprefixed URLs. Other locales use
`/{locale}/...`: first `/ru/2000nl/`. Each published locale is a real, static HTML
page. No automatic browser/IP redirects, no English copies under Russian URLs,
no artificial placeholder library pages. The product app remains separate.

`src/i18n/locales.ts` owns locale codes, names and URL prefixes.
`src/i18n/pages.ts` maps a stable page identity (e.g. `product.2000nl`) to its
**existing** language routes. This registry feeds the switch, head alternates
and sitemap. Canonical always points to the page's own URL. EN/RU reciprocal
hreflang and x-default point to corresponding pages, not section homepages.
Preview builds remain noindex and sitemap-empty. Google indexing is eligible
after intentional publication, not guaranteed or instant.

## Shared templates, separate reviewed copy

`2000nlPage.astro` owns the product-page frame and locale-specific metadata.
`2000nlLanding.astro` is one shared layout for both languages. Product copy lives
in `src/i18n/products/2000nl.{locale}.json`; shell and form labels live in
`src/i18n/ui/`. Images, product identity and app URLs remain common. Real app
screenshots are not translated or fabricated; Russian captions state the UI
language. Links to untranslated sections explicitly show EN.

The language switch is a compact current-language disclosure containing plain
links with native language names only. Explicit URL always determines the page
language. Explicit choices are saved in localStorage (`dilum-language`) for
future use; this currently does not alter routing or annotate language names.
Browser/system language does not override a direct URL. No automatic redirect or
cookie is needed; unavailable locales do not generate English fallback copies.
It includes only registered variants and uses a full navigation to avoid
persisted headers carrying the wrong locale. Theme preference survives through
existing storage. Existing English pages without translations have no fake switch.

## Updating or adding a translation

1. Edit source copy and retain product feature/access boundaries.
2. Prepare/review the translation outside public branches if unpublished content
   must remain private. Do not register draft routes. New journal drafts still
   belong in the private editorial repository.
3. Ensure the JSON keys match and all text is translated, including metadata,
   alt text, CTA, privacy/form text and errors. Preserve interest values sent to
   the backend (`Video practice`, `Reading & translation`, `Flashcards`).
4. Record review in `translation-review.json` with the SHA256 of the exact
   English JSON reviewed. English edits invalidate this marker and CI asks for
   review; do not update hashes without checking affected translations.
5. Add the locale to locales.ts and the UI/product dictionaries, then add its
   actual route to translatedPages. The `[locale]/2000nl.astro` route generates
   registered non-default locales without a per-language template copy. English URLs stay stable.
6. Build, run `npm run check:content` in production and preview modes, run waitlist
   tests when form code changes, inspect long text at mobile widths and themes.
   No production signup submissions during QA.

The waitlist backend contract and production-only storage protections are
unchanged. Local/preview form submits display a localized no-send message.

## Future library of curated collections

`src/i18n/collections.ts` distinguishes app-owned collection metadata from
localized descriptions. A stable collection ID identifies one selection across
languages. Metadata has product/appCollectionId, learningLanguage (BCP47), CEFR
level, kind (topic/exam/film/series), tags, source and an app link. Localized copy
has collectionId, locale, slug, title, description, body and review state/revision.

Example future routes: `/2000nl/collections/dutch-daily-life-a2/` and
`/ru/2000nl/collections/dutch-daily-life-a2/`. The locale describes the page,
not the language being learned. Russian descriptions can introduce Dutch words.
Vocabulary membership and learning progress remain owned by the application;
the website links via stable app collection identity instead of duplicating lists.

When real content exists, register `collection.<id>` variants, build shared
catalog/detail templates and publish intentional useful category pages. Do not
create indexable URLs for every arbitrary filter combination. This change only
provides the model/namespace; it does not claim a library exists yet.
